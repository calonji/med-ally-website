# MedAlly Clinical AI Features Across the Patient Encounter

MedAlly brings clinical documentation, decision-support context, coding and billing support, follow-up, and workflow handoffs into one connected physician workflow. The goal is to keep the work created by a patient encounter connected — while physicians remain responsible for reviewing and approving clinical outputs.

**[Start MedAlly Free](https://app.medally.ai/)**  
**[See How MedAlly Works](/how-it-works)**

Forever Free includes **10 encounters per month**.

## One Encounter Context Across the Clinical Workflow

A patient encounter creates more than a note. It can create documentation, clinical questions, lab context, treatment and follow-up work, coding needs, and downstream workflow tasks.

MedAlly is designed to keep those pieces connected to the same encounter context so the physician can review the work in a more coherent path instead of treating every task as a separate AI output.

**AI prepares. Clinicians review. Clinicians decide.**

## Documentation and Clinical Notes

MedAlly helps turn the patient encounter into structured documentation that can be reviewed and edited by the physician.

### AI medical scribe

MedAlly can use encounter context to prepare an initial clinical draft for physician review rather than requiring the note to be rebuilt from a blank page after the visit.

For the full scribe workflow, see **[MedAlly AI Medical Scribe](/ai-medical-scribe)**.

### SOAP-style clinical documentation

MedAlly prepares **SOAP-style clinical documentation** so encounter information can be organized into a familiar clinical structure.

### Physician review and editing

AI-prepared documentation remains reviewable. The physician can edit, validate, and approve the note before it is treated as final clinical documentation.

Explore the documentation workflow in **[AI Clinical Documentation](/clinical-documentation-ai)**.

## Diagnostics and Decision-Support Context

MedAlly is designed to organize clinical context that can support physician review beyond the note itself.

Depending on the workflow and deployment, that broader context can include differential-review information, relevant clinical signals, and other decision-support material connected to the encounter.

This information is **supporting context for clinician review**. It should not be presented as an autonomous diagnosis, final clinical decision, or replacement for physician judgment.

## Lab and Clinical Context Review

Clinical encounters often involve laboratory information that needs to be understood alongside the rest of the patient context.

MedAlly's broader workflow can bring lab-related context into the physician review path so it can be considered alongside documentation and the rest of the encounter information.

Keep any specific interpretation, accuracy, or automation claim out of this section unless it has been separately verified and approved.

## Treatment and Follow-Up Support

The work after an encounter can include treatment-planning context, follow-up tasks, and other next-step information.

MedAlly is designed to keep that follow-up context connected to the encounter so physicians can review what needs attention rather than losing those tasks across disconnected tools.

MedAlly should be described here as **supporting physician review and workflow organization**, not as autonomously prescribing treatment or making final care decisions.

## ICD-10/CPT Coding and Billing Context

MedAlly prepares **ICD-10/CPT coding context** around the encounter for physician review.

Keeping coding and billing context connected to the documentation can make it easier to review the administrative work associated with the same visit rather than treating documentation and coding as unrelated tasks.

Coding context should be reviewed and validated before use.

## Workflow and Operations

MedAlly is intended to help move physician-approved work through the broader practice workflow without disconnecting it from the encounter that created it.

That can include follow-up work, billing-related context, and workflow handoffs after physician review. The exact handoff depends on the MedAlly deployment.

Do not claim a specific EHR vendor, one-click transfer, automatic chart commitment, or automatic billing submission unless that behavior has been separately verified for the relevant deployment.

**[See the Full Workflow](/how-it-works)**

## Physician Review Is the Control Point

Across MedAlly's feature set, physician review remains the control point.

Before AI-prepared work moves forward, the clinician should be able to review the relevant documentation and context, make corrections where needed, and decide whether the output is ready for use.

MedAlly supports the clinical workflow. It does not replace the physician's responsibility for the final clinical record or clinical judgment.
